# Annotation Desk: working notes

A browser-only research workbench for LLM-assisted text annotation (Anthropic + OpenAI). Static Vite + React + TypeScript app, data in IndexedDB, API calls made from the browser. Published on GitHub Pages (deploy workflow in `.github/workflows/`).

## How to work with the owner
- Write in American English with curly quotes. Use Danish only when asked. The app UI is English.
- The owner is a researcher, not a developer. Explain in plain language, say what changed and what was not verified.
- Push back when something seems like a bad idea. Do not add features unasked: the owner worries about mission creep, reporting overload and files piling up on their computer.
- Scope is deliberately small: core annotation, codebook with multiple fields, replicates, gold-label agreement, recorded prompt/model/settings. Not wanted: in-app human coding, audit planner, preregistration freeze, student tutorials/examples.
- Never alter the owner's texts (no cleanup or line-joining step). Keys are never stored in exports or logs.
- Exported scripts are Python. Commit and push to the designated branch; do not open pull requests unless asked.

## Where things are
- `src/lib/prompt.ts`: prompt rendering, output schema, parsing, `flattenJsonResponse`.
- `src/lib/providers/`: Anthropic and OpenAI adapters (requests, caching, batches, model lists).
- `src/lib/store.ts`: app state, runs, batch polling.
- `src/lib/export/`: `tables.ts` (row layouts), `packages.ts` (Excel via ExcelJS, research and supplementary zips), `python.ts` (exported script and requirements).
- `src/lib/metrics.ts`: agreement statistics (validated against Python packages).
- `src/lib/background.ts`: long downloads as one job per page, tagged with its study. `src/lib/dedupe.ts`: which rows of an addition are already in the study (`sortAddition`).
- `src/components/`: UI. `tools/`: stand-alone helper scripts for the owner's corpus (`extract_pdfs.py`, `check_ligatures.py`).

## Decisions worth remembering
- One Prompt box. Each text is appended inside `<text>` tags (or placed at `{{text}}`). The fixed part before it is what gets cached.
- Effort has no "Default" option: it starts at medium and is always sent (except for models without an effort setting). Temperature is not sent to Claude models that reject it.
- No refusal fallback (removed on purpose): a label from another model is not a useful result. A refused text is a failed result.
- Failed requests are retried within the same run ("Retry failed"); "Remaining" starts a new run. Human labels can be added later from a spreadsheet (`src/lib/import/labels.ts`). Agreement has 95% bootstrap CIs (fixed seed) and human–human rows; weighted κ uses the codebook's full scale. No precision/recall/F1 (owner's choice). Run-vs-run comparison: tolerance setting (default ±1), mean difference (second − first), Excel comparison report (`buildComparisonReport`: linear and quadratic weighted κ, 2+-point and opposite-direction shares, extra "at least one non-zero" rows, Review sheet for expert review with a fixed `random` column for reproducible draws and agree split into zero/non-zero, optional breakdown by a metadata column such as era, linear-weighted Gwet's AC2). "Draw a sample…" (Select menu, `src/lib/sample.ts`): stratified, proportional, seeded; marks e.g. sample = validation and records rule, seed and method in the study description (method 3, Oct 22, 2026: strata columns ordered by name, whatever order they were ticked in; names ordered character by character, so the same in every browser; extra texts go to the groups furthest below their share; method 2 draws can still be reproduced in code with `method: 2`); the text list can be filtered by a metadata value; fields come from `src/lib/compare.ts` (codebook fields, or numeric JSON scores in plain-text runs).
- Field order in structured runs: the model writes the fields in the codebook's list order (`buildOutputSchema`; up/down arrows in the field editor), so e.g. `x_explanation` placed before `x` is written first. Results and exports use `outputFields` instead, which shows each `<score>_explanation` right after its own `<score>`. The owner's naming is `<domain>_explanation`; ordinal (−3…3) is used for integer scores, no separate integer type.
- "Saved prompts" menu (top of the Prompt section, `src/lib/savedPrompts.ts`): named prompts, each with its output mode and fields, kept in the study (`study.savedPrompts`). Loading replaces only the prompt and fields; corpus, model and run options stay put. Runs still snapshot their own prompt, so nothing here affects past runs.
- Cost estimate (`src/lib/pricing.ts`, panel `src/components/CostEstimate.tsx`): “Estimate cost” link under the run buttons opens a live panel with a USD range for All / Selected / Remaining texts. Input, answer and reasoning tokens are calibrated from earlier results with the same model (and fields / effort) when there are any, otherwise rules of thumb (3.1 chars/token on the newer Claude tokenizer, 4 otherwise; reasoning ranges per effort). Cache savings count in the low end only, Anthropic only. Built-in Anthropic prices checked against the official pricing page (date in `PRICE_SOURCES`); OpenAI prices from third-party trackers. No API calls.
- No text chunking (removed on purpose). Anthropic cache lifetime is automatic: 5 min for immediate runs, 1 hour for batches.
- Plain-text runs that return JSON are split into columns in Excel/CSV. Each explanation column goes after its scores. The owner's JSON fields are named `explanation` (not `reasoning`: Anthropic's `reasoning_extraction` refusals are triggered by JSON fields named reasoning/thinking/trace); `isExplanationKey` in `prompt.ts` accepts both names.
- Excel Results sheet shows the file name (not `doc_id`) and has no text column. CSVs keep `doc_id` as the join key.
- Scale (audit, Oct 2026): full-corpus data is far larger than a browser string (~500M characters), so the study backup is one JSON document written one record per line (`export/backup.ts`, streamed on import; older single-line backups still import) and large files go into zips as Blobs. The research zip's `study-backup.json` leaves out the logs (they are under `runs/`); Export → Study backup keeps them. A batch run over the provider's limit (Anthropic 256 MB/100k, OpenAI 200 MB/50k, with a 5% margin) is sent as several batches in the same run (`run.batch.parts`), after a warning in the run confirmation; "Retry failed" in a batch run sends a new batch (half price) into the same run (`retries[].asBatch`). Bootstrap intervals in the Agreement panel run in a Web Worker (`ci.worker.ts`).
- Results rules: any stop reason other than end_turn / stop_sequence / completed is a failed result (cut off or refused), also for plain prose. On a scale, labels that aren't numbers (e.g. "NA") are left out and reported, if most labels are numbers. With several annotations per text, each `<score>_explanation` (and the rationale) is the one from the replicate closest to the combined labels, not a merge. Plain-text JSON answers are still read strictly (the whole answer must be JSON), by the owner's earlier choice. Exports compute agreement for the same fields as the Agreement panel (`comparableFields`, so also the scores in plain-text JSON answers). A field or JSON key named like a table's own column (status, error, rationale, …) is exported as `answer_<name>`. Batch uploads are never re-sent automatically (a repeat could start a second paid batch).
- Entries (model-knowledge studies, Oct 2026): a study kind chosen under Studies → New study… ("Texts" or "Entries, from the model's own knowledge"), stored as `prompt.subject = 'entries'` (so it travels with every run snapshot; saved prompts keep the study's kind). In an entries study the right-hand workspace says entries (`src/lib/subject.ts` `words()`), takes a pasted table or a spreadsheet (no text files), the import window has no text column: the owner ticks the columns the model sees (`describeRow`), the rest (e.g. own answers) stay as metadata. Without an ID column, the ID is the first ticked column whose values all differ (so answers can be matched later); repeated IDs get a warning. Answers added later from a spreadsheet are never sent to the model. The rationale's schema description in entries studies leaves out "citing the text" (changed Oct 2026 without a new prompt version, since the version fingerprint excludes the schema; each run's settings keep the exact schema). Entries are added after the prompt in `<entry>` tags (also in annotate.py); the methods paragraph says no source texts were supplied. Text studies are unchanged. No web search: the owner decided against it (Oct 2026); don't offer it again unless asked.
- Third review (Oct 22, 2026): weighted κ weighs by value distance over the scale (identical to counting steps on whole-number scales; a 0.5 median gets partial credit); numbers outside the codebook scale are left out and reported like "NA" (`n_left_out_not_on_scale`); plain-text JSON scores take level and range from the single answers, and two runs share the range seen in either (`combineFields`); a prose replicate is left out when combining JSON answers; empty answers fail. Label columns (`goldColumnsFor`): named after the field, mostly holding its values, not notes/confidence columns, not a longer field's column (gender_role_gold); human–human rows use the run's texts. A label sheet replaces the columns it has (blank cells and unlisted texts cleared unless "keep" is ticked), conflicting repeated rows block it, its `file` column is never added; "Remove a column…" exists. One tab at a time (Web Lock, `src/lib/tabLock.ts`, wired in `main.tsx`). Runs: the early stop counts only errors pointing to the settings (400/401/403/404, not "too long"); retries record requests actually sent; a retry keeps the replaced attempt's log as `<id>#<n>` and its tokens in `run.replaced`; batch uploads are recorded before and after, an upload without an answer is looked up at the provider (`listRecentBatches`) before anything is re-sent; Cancel during a split upload stops it; deleting a copy imported from a backup leaves a shared batch running (`sharedBatches`). "Remaining" matches prompt (`promptKey`, display names excluded), model and effort. Storage failures are reported (sticky toasts, "Not saved" in the top bar, unsaved study edits retried). Build id (`__APP_VERSION__` = version+commit+date) in every export.
- Fourth round (Oct 23, 2026, after a verification of the third): Gwet's AC1/AC2 categories are exactly the scale (codebook values, or the whole numbers of the range seen for plain-text scores; q = their number): a value between two points (a 0.5 median) is split linearly between them in the chance term, a majority tie "a | b" equally among its categories; labels not on the scale or not a category are left out and reported (`leftOut`, with `range`); missing-value markers (NA, N/A, none, -, …; `isMissingLabel`) always are, unless a category; for plain-text scores see the fifth round. Yes/no fields have categories false/true and read y/n. Label columns: missing markers don't count against a column; `author_*` columns are not labels; `labelPairs().skipped` lists columns not used and why (shown under Export); `knownFieldNames` also reads plain-text JSON keys. A label sheet replaces values only for the texts it lists (blank clears); "also remove values of texts not listed" is an opt-in checkbox; a results file exported by this app can't be added as labels. Pasted tab tables: read literally unless only Excel's quoting gives every row the header's cells; repeated column names become note, note_1; a header without commas or semicolons means one value per line. Early stop: see the fifth round. Replaced attempts' tokens are stored on each result (`replacedUsage`); `run.replaced` and retry counts are derived from stored results. "Remaining" also holds back texts of an upload of unknown outcome (`unknown`, `unknownRuns`); a found retry upload is recorded as that retry (`UploadAttempt.retryAt`). One-tab lock: see the fifth round. Logs record settings not sent (`omitted`, e.g. day-one `fallbacks`); `requestAsSent` shows requests as sent.
- Fifth round (Oct 23, 2026, after the third verification). Statistics: plain-text scores carry `range` (min/max of the model's single answers, whole or not; two runs union them); `agreement` grows the scale from it through the label values (`grownScale`; step and limits: see the sixth round), so a −3 next to answers −2…3 is kept while 9, 33 or 99 are left out (`leftOut.range` = grown scale); labels kept outside the model's range are reported as `outsideAnswers` (panel note only, not exported, to avoid more reporting); human–human rows use the same rule seeded by the run's range; weights and Gwet's q are the whole numbers of the grown scale. On any scale (codebook, plain-text, or category codes that are all numbers, judged on their range at every level, so a 1.5 median counts as a disagreement) a number off it is always left out, even where most labels are; only mostly words fall back to being compared as they are. A missing marker counts as a blank label everywhere labels are counted (`labelValue`). A label column whose name minus marker words (gold, human, coder, rater, annotator, pilot) names a longer field belongs to that field (so race_old_gold is skipped for race). The Workbench's “Disagree with” follows the same rules (`comparableLabel`). Runs: early stop (first runs and retries alike) only when the first 3+ answered requests all failed in a way that hits every request (no connection; 401/403/404; OpenAI 429 with code insufficient_quota or billing_not_active; Anthropic 400 “credit balance”; other 400s unless per-text, and only with the same message once ids are removed) and they come from 2+ texts; a stopped retry keeps the run's status with “Retry stopped: …”. OpenAI batches are created with metadata {annotation_desk_run, annotation_desk_upload} and the input file id is saved before batches.create; a lost upload is matched by those; older uploads and Anthropic by request count among batches no run knows, created in the upload's time window (see the sixth round). Deleting a run or study with an upload of unknown outcome looks it up first and cancels it if found, else asks; Retry failed on such a run asks nothing before its free lookup. A batch this page knows is never also “unknown”; results stored while the run record can't be saved are not fetched again by quiet checks. Retries entries written now carry `counted: 'sent'`; entries without it in runs of the published version (bare appVersion, e.g. "0.1.0") hold planned counts, so exports count those from the stored answers as a lower bound (“at least N”, `retryCounts`/`retriedRequests` in view.ts, `retryNotes` in tables.ts) and say that version kept no replaced attempts' tokens; an interrupted retry (`interrupted`) counts the requests answered, also reported as “at least”. Interrupted runs finish at their last answer. Exports: runs sharing a number are named apart everywhere (see the seventh round); backups are built from the stored records, not today's in-memory reading. Import: one-column pastes read Excel's quoting per cell when well-formed; tab pastes take the first reading (literal, quoted, quoted with tabs) that fits every row, else the one with fewer misfit rows; warnings give source line numbers; column names are trimmed (values never), a nameless column is column_<n> (no __EMPTY); pasted texts are never trimmed. Label sheets: the app's results tables (wide, long, by replicate) are recognized by their own columns or copied explanations and blocked; same-name entries listed by name block the sheet. Import dialogs can't be cancelled while saving, ignore their button for 0.5 s after opening, and stay open if saving fails. One-tab lock: a waiting tab asks for the lock only when the user turns to it (visibilitychange, focus, or Open here; a few quick re-asks while focused), one request at a time, never polling. Storage layout unchanged (F51): a label sheet, sample or column removal rewrites the texts it touches, and the failure message gives the free space needed.
- Sixth round (Oct 23, 2026, after the fourth verification). Statistics: plain-text scores grow from the model's range by max(3, width/2) points (`scaleStep`), and only when every answer lies within −10…10 (`ratingRange`: a rating scale, where a far-off number is a code); with larger numbers (percentages, years, counts) no number is left out for its distance. Answers within −10…10 can't be told from a rating scale, so there 9 or 99 next to −3…3 is left out, while 7/8/9 next to a 1–5 item are kept (within 3 points); the panel and exports name what was left out. combineFields gives a numeric codebook against plain-text scores the codebook's scale at any level. The panel's two label columns find their field from any run, judged on every labelled text (`labelPairs` {valueDocs, known}); exports judge on the run's texts. Label marker words also include expert, final, consensus, standard, coded, reference, adjudicated, manual; a field implied by a column name counts only when it extends the field at the end (race_negative for race). The Workbench's “Disagree with” reads plain-text JSON scores. Runs: deleting a run or study asks every question before anything is cancelled; it never cancels an unknown upload's batch that another study here (a backup copy) shares. Batches of deleted runs (and batches a delete cancelled) go into localStorage `annotation-desk-deleted-batches` (ids only, last 500) and are never matched by request count, nor is a batch the provider lists as cancelled or expired (the lookup is then unsure and asks); runs in the page's memory count as known; the count-match window is 10 minutes either side (`CLOCK_MARGIN_MS`); an upload's own batch held by a backup copy (same `since`, or its metadata/file) is matched and shared. A refused retry upload keeps the earlier unknown upload. A retry stopped by Cancel counts the requests begun (`retries[].unanswered` without an answer); an interrupted retry with no answer is kept as {requests: 0, interrupted}. When only the run record can't be saved, the notice says the results were saved (`BatchPart.resultsSaved`). Runs the published build marked “Interrupted” finish at their last answer (in memory). addDocs compares only with texts stored before the import. A result keeps its replaced attempts' request times (`replacedAt`). The lock re-asks a few times on page load; a run that got an answer within 2 minutes when a study opens raises a warning about an older version's tab still sending. Import: a quoted span is one cell only if it doesn't start or end with a line break or tab and, holding a tab, stays on one line; when no reading fits every row, the fewest misfits wins; delimiter-only rows are skipped in the app (right line numbers). Label sheets: strong export columns (n_ok, n_error, prompt_hash, response_id, model_requested, …) block a sheet even with no known field; weak ones (status, error, study, run, …) never alone; field names also come from the current and saved prompts; a column is called the model's only when its values match the model's answers. Exports: published-version retries (batch too) are counted from the stored answers in their window, including replaced attempts, as a lower bound; `runName`/`runTitle(run, runs)` live in view.ts and are used on every screen; metadata.json's run has its name and id; a replaced attempt's line in responses.jsonl has status, error and parse_error; “partly annotated” counts only texts with a label; the comparison report says when a run was unfinished; plain-text runs' packages have no codebook.json, no rationale_requested and output_schema.json only with a schema.
- Seventh round (Oct 24, 2026, after the fifth verification). Statistics: a numeric codebook combined with plain-text scores keeps the codebook's own ends as `range`, and `agreement` takes the midpoint from it (a stray plain-text 4 next to −3…3 doesn't move "opposite direction"); `allowed` is still widened. The panel's identifier notice (`looksLikeIdColumn`) never hides a column the exports pair with the field, nor a numeric field whose cells are mostly numbers once missing markers are blank. Two label columns whose field only the current or a saved prompt names take it from the prompt (`promptField`; plain-text prompts: no range, no distance rule). “Disagree with” compares the field the chosen column is named after (`namedField`), for structured and plain-text runs alike (`codebookFields`, `compareFieldFor`). Draw a sample: texts whose column already holds another value are not eligible (samples stay disjoint; the dialog and note say how many, a count when more than three values); redrawing the same value keeps its texts eligible. Runs: deleted batches are remembered as {id, since, requests}; a remembered batch with the upload's own `since` is that upload's (a copy restored from a backup adopts it); a remembered batch the provider lists as cancelled/expired makes another upload's lookup unsure. A retry's upload carries `earlier` (the run's earlier upload of unknown outcome); a count-only find that may predate the retry is recorded as either's (`eitherRetry`) and its answers decide, so nothing is counted as re-sent that never went up. Save-failure marks are kept per run and batch (`markKey`). addDocs skips an item identical to a stored text also under a suffixed ID (John Smith_2), and within one import only rows identical in every column. Store messages name runs by `runName`; runs load in `runOrder` (number, then start time). Run names for shared numbers use the start time (`runTag`, e.g. 5-20261022-221754Z, UTC; milliseconds or the id only for ties), so they survive a backup import. Exports: the research and supplementary zips are written by a streaming writer (`ZipWriter`, fflate 0.8.2 ZipDeflate level 3, Blob parts of ~4 MB, ZIP64 past 4 GB; the Export tab shows the file being written): about 1 GB peak instead of 5 at 20k-character texts. Oct 18–20 batch retries (answers dated at the run's start, `undated`) count the number they recorded. The READMEs say “stored” for logs and why when requests may be missing (`logGaps`); the methods text puts all retry notes in one parenthesis. Label sheets: only the columns that would be added are judged (a sheet keyed by response_id is accepted); a short label column counts as the model's only when identical to one run's answers (one replicate or its combined labels) on every one of 10+ texts with 2+ values, never in entries studies (correct facts can equal the model's); explanations still match any answer.
- Eighth round (Oct 24, 2026, after the sixth verification). Statistics: combineFields treats a Yes/no field against plain-text 0/1 scores as the Yes/no field (generalized in the ninth round); against such scores a coder's yes/no label reads as 1/0 (`labelValue`), so it is paired and compared. Only structured prompts give a field to two label columns (`promptField`, current then saved); a plain-text prompt's hidden variables never give a field, codebook or scale. “Disagree with” judges each text on the scale of the run that gave its value (`compareRows`: a structured run's own codebook; a plain-text run's range of the answers shown). Krippendorff's ordinal distance uses running totals (same results, much faster on wide scales). Runs: `UploadAttempt.earlier` keeps the earlier upload's `retryAt` (`eitherRetry.earlierAt`); on collection the retry whose request names the answers carry is counted (the later, the earlier, or none for the run's own upload). Deleted batches are remembered as {id, since, requests, orSince}, a batch found as either's under both upload times. Imports: within one table, rows differing only in their ID are all added; across imports, a row with a made-up ID is already here when a stored text has its text and the same value in each of its columns (`sortAddition`, also used by the table dialog's counts). Samples: a note names each earlier draw it left out (date, n of eligible, seed); a redrawn sample's note is kept, marked as replaced, while another draw depends on it; the dialog names dependent samples before a redraw. Results reach the screen every 250 ms, or every second once a study holds more than 20,000. Exports: long downloads (Excel, research and supplementary zips, study backup, comparison report) run one at a time as a job in `src/lib/background.ts` that outlives the tab; the Export tab remembers which study its download is for, the page asks before closing or reloading while one runs, and progress lines name each step before it starts. Agreement figures for exports are computed in the report worker (`agreementData` sends the study without texts). Label sheets: the “other columns that may hold the model's answers” list is hidden only when the sheet has every field of one of this study's runs (structured fields, or a plain-text run's JSON keys) and holds answers stored here; a plain-text prompt's `response` column alone never counts.
- Ninth round (Oct 24, 2026, after the seventh verification; the last fix round of the review). Downloads: each background job records its study (`startBackground(kind, label, study, choices)`, `buildingFor`, `useBuildingFor`). While a download of a study is being built (it reads stored results and logs as it goes), the store refuses, with a message naming it (`waitForDownload`): deleting the study or a run, Retry failed, and collecting batch results (quiet checks skip the study; Check now is disabled and says why). A download first waits for a batch check of its study already running (`batchChecksDone`), and isn't built if another study was opened meanwhile. Deleting a run or study waits for a running batch check of it and no check starts meanwhile, so no results are left under a deleted run. The study backup, the research zip and a supplementary package with logs wait while a run or Retry failed is being sent (they would hold answers from before and after); the Excel workbook and the package without logs show the results so far. Another study's tabs name a report being built elsewhere; the Export tab shows the build's own run and options. Yes/no: a field is a dichotomy (`dichotomy` in compare.ts) when it is a Yes/no field, a Category whose values are exactly yes/no or true/false, a codebook of exactly 0 and 1, or plain-text scores marked `zeroOne` (every answer within 0…1, or more than half exactly 0 or 1 and at most 1% within 3 points outside; codes further off such as 9 are not counted). Two runs are compared as yes/no when both are dichotomies and at least one is in words; a value that is neither (a 0.5 median, a 9) is left out and reported. Two runs that both give 0/1 as numbers are compared as numbers. A yes/no tie reads the same in every encoding (“0 | 1” → “false | true”). The comparison report's Review sheet leaves out exactly the pairs its Summary leaves out. Imports again (`dedupe.ts`): a table row with an ID of its own is judged by that ID, also under a file column (a renumbered table adds its shifted rows again, counted in the dialog first); in entries studies details count as the same whatever the order of their lines. Samples: a note that names a draw depends on it wherever it sits; a redraw's own new note counts as dependent (`replaceSampleNotes(…, adding)`). Results-sheet notice: each plain-text run's JSON keys come from its first 20 answers, so the “other columns” list doesn't depend on load order.
- Corpus: 3,080 articles (937 Markdown files extracted from scholarly PDFs, the rest .txt), all with unique file names; a metadata file (era, journal, pilot, …) covers every article and is added with "Add labels from a spreadsheet". Of the Markdown files, about 15 have lost fi/fl/ff letters and 36 have stray `<mark>` tags. The owner chose to leave them as they are.
