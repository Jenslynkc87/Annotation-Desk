# Annotation Desk: working notes

A browser-only research workbench for LLM-assisted text annotation (Anthropic + OpenAI). Static Vite + React + TypeScript app, data in IndexedDB, API calls made from the browser. Published on GitHub Pages (deploy workflow in `.github/workflows/`).

## How to work with the owner
- Write in American English with curly quotes. Use Danish only when asked. The app UI is English.
- The owner is a researcher, not a developer. Explain in plain language, say what changed and what was not verified.
- Push back when something seems like a bad idea. Do not add features unasked: the owner worries about mission creep, reporting overload and files piling up on their computer.
- Scope is deliberately small: core annotation, codebook with multiple fields, replicates, gold-label agreement, recorded prompt/model/settings. Not wanted: in-app human coding, audit planner, preregistration freeze, student tutorials/examples.
- Never alter the owner's texts (no cleanup or line-joining step). Keys are never stored in exports or logs.
- Exported scripts are Python. Commit and push to the designated branch; do not open pull requests unless asked.

## Where things are
- `src/lib/prompt.ts`: prompt rendering, output schema, parsing, `flattenJsonResponse`.
- `src/lib/providers/`: Anthropic and OpenAI adapters (requests, caching, batches, model lists).
- `src/lib/store.ts`: app state, runs, batch polling.
- `src/lib/export/`: `tables.ts` (row layouts), `packages.ts` (Excel via ExcelJS, research and supplementary zips), `python.ts` (exported script and requirements).
- `src/lib/metrics.ts`: agreement statistics (validated against Python packages).
- `src/components/`: UI. `tools/`: stand-alone helper scripts for the owner's corpus (`extract_pdfs.py`, `check_ligatures.py`).

## Decisions worth remembering
- One Prompt box. Each text is appended inside `<text>` tags (or placed at `{{text}}`). The fixed part before it is what gets cached.
- Effort has no "Default" option: it starts at medium and is always sent (except for models without an effort setting). Temperature is not sent to Claude models that reject it.
- No refusal fallback (removed on purpose): a label from another model is not a useful result. A refused text is a failed result.
- Failed requests are retried within the same run ("Retry failed"); "Remaining" starts a new run. Human labels can be added later from a spreadsheet (`src/lib/import/labels.ts`). Agreement has 95% bootstrap CIs (fixed seed) and human–human rows; weighted κ uses the codebook's full scale. No precision/recall/F1 (owner's choice). Run-vs-run comparison: tolerance setting (default ±1), mean difference (second − first), Excel comparison report (`buildComparisonReport`: linear and quadratic weighted κ, 2+-point and opposite-direction shares, extra "at least one non-zero" rows, Review sheet for expert review with a fixed `random` column for reproducible draws and agree split into zero/non-zero, optional breakdown by a metadata column such as era, linear-weighted Gwet's AC2). "Draw a sample…" (Select menu, `src/lib/sample.ts`): stratified, proportional, seeded; marks e.g. sample = validation and records rule, seed and method in the study description (method 3, Oct 22, 2026: strata columns ordered by name, whatever order they were ticked in; names ordered character by character, so the same in every browser; extra texts go to the groups furthest below their share; method 2 draws can still be reproduced in code with `method: 2`); the text list can be filtered by a metadata value; fields come from `src/lib/compare.ts` (codebook fields, or numeric JSON scores in plain-text runs).
- Field order in structured runs: the model writes the fields in the codebook's list order (`buildOutputSchema`; up/down arrows in the field editor), so e.g. `x_explanation` placed before `x` is written first. Results and exports use `outputFields` instead, which shows each `<score>_explanation` right after its own `<score>`. The owner's naming is `<domain>_explanation`; ordinal (−3…3) is used for integer scores, no separate integer type.
- "Saved prompts" menu (top of the Prompt section, `src/lib/savedPrompts.ts`): named prompts, each with its output mode and fields, kept in the study (`study.savedPrompts`). Loading replaces only the prompt and fields; corpus, model and run options stay put. Runs still snapshot their own prompt, so nothing here affects past runs.
- Cost estimate (`src/lib/pricing.ts`, panel `src/components/CostEstimate.tsx`): “Estimate cost” link under the run buttons opens a live panel with a USD range for All / Selected / Remaining texts. Input, answer and reasoning tokens are calibrated from earlier results with the same model (and fields / effort) when there are any, otherwise rules of thumb (3.1 chars/token on the newer Claude tokenizer, 4 otherwise; reasoning ranges per effort). Cache savings count in the low end only, Anthropic only. Built-in Anthropic prices checked against the official pricing page (date in `PRICE_SOURCES`); OpenAI prices from third-party trackers. No API calls.
- No text chunking (removed on purpose). Anthropic cache lifetime is automatic: 5 min for immediate runs, 1 hour for batches.
- Plain-text runs that return JSON are split into columns in Excel/CSV. Each explanation column goes after its scores. The owner's JSON fields are named `explanation` (not `reasoning`: Anthropic's `reasoning_extraction` refusals are triggered by JSON fields named reasoning/thinking/trace); `isExplanationKey` in `prompt.ts` accepts both names.
- Excel Results sheet shows the file name (not `doc_id`) and has no text column. CSVs keep `doc_id` as the join key.
- Scale (audit, Oct 2026): full-corpus data is far larger than a browser string (~500M characters), so the study backup is one JSON document written one record per line (`export/backup.ts`, streamed on import; older single-line backups still import) and large files go into zips as Blobs. The research zip's `study-backup.json` leaves out the logs (they are under `runs/`); Export → Study backup keeps them. A batch run over the provider's limit (Anthropic 256 MB/100k, OpenAI 200 MB/50k, with a 5% margin) is sent as several batches in the same run (`run.batch.parts`), after a warning in the run confirmation; "Retry failed" in a batch run sends a new batch (half price) into the same run (`retries[].asBatch`). Bootstrap intervals in the Agreement panel run in a Web Worker (`ci.worker.ts`).
- Results rules: any stop reason other than end_turn / stop_sequence / completed is a failed result (cut off or refused), also for plain prose. On a scale, labels that aren't numbers (e.g. "NA") are left out and reported, if most labels are numbers. With several annotations per text, each `<score>_explanation` (and the rationale) is the one from the replicate closest to the combined labels, not a merge. Plain-text JSON answers are still read strictly (the whole answer must be JSON), by the owner's earlier choice. Exports compute agreement for the same fields as the Agreement panel (`comparableFields`, so also the scores in plain-text JSON answers). A field or JSON key named like a table's own column (status, error, rationale, …) is exported as `answer_<name>`. Batch uploads are never re-sent automatically (a repeat could start a second paid batch).
- Entries (model-knowledge studies, Oct 2026): a study kind chosen under Studies → New study… ("Texts" or "Entries, from the model's own knowledge"), stored as `prompt.subject = 'entries'` (so it travels with every run snapshot; saved prompts keep the study's kind). In an entries study the right-hand workspace says entries (`src/lib/subject.ts` `words()`), takes a pasted table or a spreadsheet (no text files), the import window has no text column: the owner ticks the columns the model sees (`describeRow`), the rest (e.g. own answers) stay as metadata. Without an ID column, the ID is the first ticked column whose values all differ (so answers can be matched later); repeated IDs get a warning. Answers added later from a spreadsheet are never sent to the model. The rationale's schema description in entries studies leaves out "citing the text" (changed Oct 2026 without a new prompt version, since the version fingerprint excludes the schema; each run's settings keep the exact schema). Entries are added after the prompt in `<entry>` tags (also in annotate.py); the methods paragraph says no source texts were supplied. Text studies are unchanged. No web search: the owner decided against it (Oct 2026); don't offer it again unless asked.
- Third review (Oct 22, 2026): weighted κ weighs by value distance over the scale (identical to counting steps on whole-number scales; a 0.5 median gets partial credit); numbers outside the codebook scale are left out and reported like "NA" (`n_left_out_not_on_scale`); plain-text JSON scores take level and range from the single answers, and two runs share the range seen in either (`combineFields`); a prose replicate is left out when combining JSON answers; empty answers fail. Label columns (`goldColumnsFor`): named after the field, mostly holding its values, not notes/confidence columns, not a longer field's column (gender_role_gold); human–human rows use the run's texts. A label sheet replaces the columns it has (blank cells and unlisted texts cleared unless "keep" is ticked), conflicting repeated rows block it, its `file` column is never added; "Remove a column…" exists. One tab at a time (Web Lock in `main.tsx`). Runs: the early stop counts only errors pointing to the settings (400/401/403/404, not "too long"); retries record requests actually sent; a retry keeps the replaced attempt's log as `<id>#<n>` and its tokens in `run.replaced`; batch uploads are recorded before and after, an upload without an answer is looked up at the provider (`listRecentBatches`) before anything is re-sent; Cancel during a split upload stops it; deleting a copy imported from a backup leaves a shared batch running (`sharedBatches`). "Remaining" matches prompt (`promptKey`, display names excluded), model and effort. Storage failures are reported (sticky toasts, "Not saved" in the top bar, unsaved study edits retried). Build id (`__APP_VERSION__` = version+commit+date) in every export.
- Corpus: 3,080 articles (937 Markdown files extracted from scholarly PDFs, the rest .txt), all with unique file names; a metadata file (era, journal, pilot, …) covers every article and is added with "Add labels from a spreadsheet". Of the Markdown files, about 15 have lost fi/fl/ff letters and 36 have stray `<mark>` tags. The owner chose to leave them as they are.

## Checks before pushing
`npx tsc --noEmit -p .`, `npx vitest run`, `npx vite build`.

## Publishing
The site deploys from the repository's default branch, `claude/gifted-bell-is85me`. Work goes to the session's own branch; only when the owner says "publish", fast-forward the default branch to it (`git push origin HEAD:claude/gifted-bell-is85me` after checking it is a fast-forward). Batch changes; don't publish unasked. No need to watch the deploy: GitHub emails the owner if it fails.
